# 본선 발표 근거 강화 — 기기 검증 계획

작성 2026-08-14 · 발표자료 v2(15p) 기준 · 실행 대본은 [DEVICE_TEST_SCRIPTS.md](../docs/verification/DEVICE_TEST_SCRIPTS.md) 참조

## 0. 원칙 (먼저 읽기)

1. **최종 서명 APK만 사용** — `output/submission/APP.apk`를 그대로 설치한다.
   재빌드·재서명 금지(SAMPLE_EXPORT가 APK 해시를 결속). debug 빌드로 얻은 수치·화면은
   발표에 쓰지 않는다 — "발표 내용 = 제출물"이라는 주장을 지키기 위해.
2. **제출물은 동결** — 이 검증은 앱을 고치기 위한 것이 아니라 ① 발표자료에 넣을 실측
   수치, ② 스크린샷, ③ 질의응답 즉석 재현 능력을 얻기 위한 것이다.
3. **수치는 2회 재현된 것만 발표에 넣는다.** 한 번 나온 값은 근거가 아니다.
4. 캡처 규칙: 합성 데이터만 화면에 나오게. 상태바의 통신사·계정·알림 등 개인 식별
   요소가 걸리면 잘라낸다(개인정보 작성 금지 규정).
5. 알림 권한은 **첫 실행에서 거부**한 상태로 진행 — "선택 권한" 주장과 화면을 일치시킨다.

## A. 발표자료에 들어갈 것 (8/17까지 — 최우선)

### A1. VIL 실측 — 슬라이드 11의 `[본선 전 실측해 수치로 교체]` 채우기 ★★★

대본 **S9** (full/claim-off 짝 비교, 예상 40~60분 ×2회).

- 절차 요약: 깨끗한 상태 → `비교 실행` → paired 시작점 **한 번만** 생성 → full arm으로
  S1+S2 수행 → claim-off arm 전환(준비 버튼 재클릭 금지) → **같은 식당·같은 메뉴·같은
  문장**으로 반복.
- 기록할 것:
  - [ ] pair ID, state·catalog digest (두 arm 동일 확인)
  - [ ] 주문 1(마라향)·주문 2(금손분식) 각각의 `확인 N건 남음` 최댓값 — full / claim-off
  - [ ] 두 arm의 추천 후보·순서가 동일한지 (이득이 추천에서 오지 않았다는 증거)
  - [ ] claim-off도 주문을 끝까지 완료했는지 (비교군 공정성)
  - [ ] guardrail 위반 0 (잘못된 적용·중복 action 없음)
- 산출물: "같은 절차, full N회 vs claim-off M회 (−xx%)" 표 + 비교 화면 캡처.
- **주의**: 8/4에 저장 기본값을 바꿨으므로 그 이전 측정치는 무효 — 반드시 새로 잰다.
- 반영 후 **슬라이드 13의 한계 목록에서 "VIL 수치 실측 전" 항목을 갱신**한다
  (실측 완료로 바꾸거나 삭제 — 자료 정합성).

## B. 질의응답(C5) 대비 — 8/19~20

### B1. "5분 즉석 재현 코스" 리허설

심사위원이 "직접 보여달라"고 할 때를 대비해, 깨끗한 상태에서 시작하는 최단 코스를
시간 재며 2회 연습:

1. E1 압축(마라향: 조건→맵기·고수 저장) — 2분
2. E2 재사용(금손분식: 자동 채움 + 출처 문구 + 질문 감소) — 1분
3. `이 process 종료` → 복원 + epoch 증가 확인 — 1분
4. 품절 event → 부분 재개방 — 1분
5. `내 취향과 기억`에서 철회 → 다음 주문에서 그 항목만 재질문 — 1분

각 단계에서 **말로 짚을 화면 요소**(출처 문구, 검증 정보, 보존됨 표시)를 정해 둔다.

### B2. artifact 열람 연습 — "이 주장의 근거는 이 파일"

소리 내어 설명하는 연습 (파일 → 필드 → 화면 대조):

- [ ] `SAMPLE_EXPORT/PROBE_RESULT.json`: evidence_ids 35개 ↔ `evidence/` 실제 파일 대조
- [ ] `state_before/after_sha256` digest 연쇄 — 한 step 골라 앞뒤 연결 설명
- [ ] `process_epoch` 0→1 전환 지점 (step 09)
- [ ] `RUNTIME_IDENTITY.json`: `cumulative_invocations: 0`, `model_backend_frozen_id: NOT_USED`
  — "모델·네트워크 미사용" 주장의 결정적 근거
- [ ] `MISSION_LOCK.json`: 동결된 claim ↔ 발표 2p 문구 일치
- [ ] 소스에서 짚을 위치 2~3곳: fact type 정의, projection 필터, idempotency key 생성
  (파일 경로를 미리 메모)

### B3. 예상 질문 리스트

별도 문서로 준비 권장 (요청 시 작성): "왜 LLM을 안 썼나", "실제 배달앱에 어떻게 이식하나",
"claim-off가 불리하게 설계된 것 아닌가", "VIL 감소가 안전 희생 없이 왔다는 보장은",
"PRACTICE-B 미실행인데 일반화 근거는" 등 — 각 답변을 artifact와 연결.
